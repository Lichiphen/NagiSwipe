# 個人用LOGの設計と作業記録

NagiMangaには、漫画をファイルで保存する管理画面があります。
そこに、短い文章と画像を気軽に投稿できるLOGを追加します。
作業ブランチは `feature/personal-log-cms` です。

## 保存のしかた

投稿は1件ごとに保存します。ノートのページを1枚ずつ増やす形です。
データベースや外部のJavaScriptライブラリは追加しません。
ログイン、CSRF対策、画像の読み直しはNagiMangaと共用します。

URLの投稿番号は、日本時間の `20261004123033` のような日時です。
同じ秒に重なった場合は `20261004123033-02` とします。
番号は公開するときに決まり、編集しても変わりません。
下書きは別の番号で保存し、公開するまでは外から読めません。

## 画面と本文

NagiMemoの `skin-cover.html`、`common-ui.js`、`drag-drop-upload.js` を参考にします。
画面、投稿操作、保存処理を別のファイルに分けます。
NagiMemoのてがろぐ用の処理や記号はコピーしません。

パソコンは投稿欄と一覧、スマホは「書く」から開く投稿画面です。
選んだ文字を太字にでき、画像は選択、貼り付け、ドロップで追加できます。
本文のHTMLは文字として表示します。

漫画は、新しい作品からタイトルと表紙を選びます。
本文には `[Mangaタイトル名]` を入れ、別に作品IDを保存します。
同名の作品には短い識別番号を添えます。
タグは本文の好きな位置へ移せます。
パスワード付き漫画の表紙は公開側へ出しません。

画像にも番号を付けます。差し替えても本文のタグは変わりません。
差し替えた画像には新しい版の番号を付け、古いキャッシュを避けます。
未使用画像と下書きの画像は、公開窓口から読めません。

## 確認すること

投稿、編集、下書き、公開、画像追加、差し替え、漫画選択を確認します。
同じ秒の投稿、二重送信、別タブの編集も確認します。
管理者以外の書き込み、HTMLの実行、非公開画像の漏れを確認します。
漫画の既存テストと、LOGのバックアップ・復元も実行します。
スマホの投稿画面と、画像・漫画ビューアーはブラウザで確認します。

## 追加した仕様と判断

公開入口を `index.php` にして、URLは設置ディレクトリとクエリだけにしました。
以前の `log.php` は、新しいURLへ301転送します。
ファイル名を隠す処理と、認証・入力・保存先の保護は別の役割です。

カテゴリは、投稿時の作成・選択と、設定画面からの改名に対応します。
ハッシュタグは本文から抽出し、直近8件を投稿欄へ表示します。
改名時は、公開済みの本文と下書きも書き直し、古い編集からの上書きを防ぎます。

サイドメニューに、カレンダー、最新3件、分類、最終更新日を追加しました。
スマホでは、ひし形のボタンに三本線を描き、右上へ固定します。
投稿の白い部分は幅いっぱいに広げ、文字の内側に余白を残しました。
ライト3種類・ダーク3種類の設定、共通アイコン、丸いスクロールバーを追加しています。
色見本は全体を選択でき、スマホのラジオボタンは見本の下です。

トップとカテゴリの先頭ページだけを検索の対象にします。
個別投稿、タグ、日付、月、2ページ目以降はnoindexです。
個別OGPは本文の最初の画像を優先し、画像がなければ設定した共通OGPを使います。
漫画カードの表紙と、投稿URLのOGPは別に選びます。

画像収集を示すUser-Agentと、同じIPからの画像大量取得を404で拒否します。
LOG画像と漫画画像に共通の制限を使います。
文章閲覧のAIを一律に拒否せず、UA偽装・低頻度・分散取得の完全排除は保証しません。
404のブラックホールはCSSで描き、動きを減らす設定にも対応しました。

キャッシュバスターは、版番号だけでなくJS・CSSの内容から作ります。
漫画CSSだけを変えたときも、CSSを読み込むJSの番号を変えます。
画像差し替えは、同じ画像IDと新しい版番号を使います。

## タイトル行の表示を修正

追加の依頼に合わせて、入力本文の1行目をタイトル、2行目以降を本文にしました。
タイトルの文を本文で繰り返さず、公開・管理一覧・プレビューで同じ表示にします。
1行目に画像・漫画のタグがある場合は、本文へ残して表示します。
投稿と編集欄の原文は変更しません。
長いタイトルは見出しに全文を出し、共有情報とサイドメニューだけ80文字で省略します。
一覧ファイルの形式番号を5にして、以前のタイトル情報も原本から読み直します。
この変更を含めて、別AgentがLOG153項目を2回、敵対検証99項目を確認しました。

## 管理者の投稿と自分専用Memo

既存のCMSをコミット5e46a72に保存しました。追加の依頼は同じブランチで作業し、プッシュしません。
ログイン中のサイトでは、メニューの名称を「管理ページ」にし、記事に編集ボタンを追加します。
ログイン・管理ページへのリンクをまとめたブロックは、設定で隠せます。
先頭の記事の上に投稿欄を置き、スクロールで隠れるとペンのSVGと「書く」を表示します。
スマホとパソコンの両方から、浮遊ボタンで投稿画面を開けます。

LOGの公開範囲は、全体公開と自分専用Memoから選びます。
Memoでは、管理者としてログインした場合だけ記事とLOG画像を読めます。
未ログイン・ゲスト・失効したログインでは404を返します。漫画の公開範囲は別の設定です。
認証Cookieの範囲を管理フォルダから設置ルートへ移し、既存ログインも移行します。
ログイン中のサイト・画像はprivate,no-store、公開応答にはVary:Cookieを指定します。

カテゴリ・ハッシュタグは「LOG・投稿」へ移します。
設定はNagiMANGA、LOG、共通・安全のタブに分け、各ブロックの保存先を分かるようにします。
トップの管理メニューは、ペンのSVGと3つの主な入口をまとめます。
作品用の追加操作、バックアップ、更新、ログアウトは「管理メニュー」に置きます。

サイトのトップ、日付・月、カテゴリ、タグは共通で10件表示を標準とし、設定で1〜100件へ変えられます。
管理一覧は20件を標準とし、一覧の上部で1〜100件へ変えられます。管理側の件数はセッションに保存します。
管理一覧にはテーブルを使わず、日時、タイトル、小さな画像、編集、削除を短い行で並べます。

## フッター・分類順序・一括削除

フッターは「LOG → サイト下部の表記」で表示を選び、1行200文字まで自由に入力できます。
HTMLは実行せず文字として表示します。空欄でも表示を隠します。
カテゴリとハッシュタグは、持ち手のドラッグと上下ボタンで並び替えます。
マウスとタッチをPointer Eventsで処理し、変更はその場で保存します。
分類の更新番号を照合し、別画面の変更を上書きしません。保存失敗時には表示の順番も戻します。
投稿欄の最近8件のタグは、使用履歴から選ぶ機能として維持します。

管理一覧に「記事を見る」を追加します。下書きは公開URLへ進めず、編集から確認します。
一覧の上部で一括削除モードを開き、個別選択・ページ内全選択・選択件数を表示します。
確認画面を経てから削除し、一括選択中は浮遊する投稿ボタンを隠します。

画像の清掃範囲は利用者に確認し、「その記事だけで使っていた画像・サムネイル・関連記録も削除する」で了承されました。
ほかの記事・下書き・アイコン・OGPで使っている画像は残します。
無関係な未使用画像、漫画の原本、分類の設定、セキュリティログは一斉に消しません。
保存済みのローカル投稿データは維持し、削除試験は専用コピーで行います。

削除する全記事の更新番号を事前確認し、その後、一時フォルダへ記事と専用画像を移します。
共有画像の参照は一覧用ファイルではなく、残る投稿の原本から確認します。
受付記録と一覧情報も更新し、途中で失敗した場合は記事・画像・受付記録・一覧を戻します。
正常時には一時フォルダを消し、空になった年・下書きフォルダも整理します。
空の案内用index.htmlだけが残る場合も整理し、ほかの内容を持つフォルダは消しません。

停電、強制終了、書き込み権限やディスクの故障まで、完全な復旧を保証する設計にはしていません。
削除は取り消せないため、READMEでバックアップからの復元方法を説明します。
新規投稿の再送防止記録も整理するので、古い新規投稿欄の再送は新しい記事になる場合があります。
削除後は古い投稿欄を閉じ、画面を開き直すよう案内します。

フッターと分類の並び順をLOGバックアップに含め、旧形式の復元では保存先の既存設定を保ちます。
ローカル起動用start_preview.ps1は、保存済みのLOGを再利用します。データの再作成や初期化を行いません。
Windows PowerShell5でも使えるよう、UTF-8のBOMと、引用符を壊さないPHP要件検査にしました。
